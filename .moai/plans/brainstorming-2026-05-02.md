# Regula 시스템 브레인스토밍 확정 사항

> 작성일: 2026-05-02  
> 세션 유형: 시스템 구축 철학 및 아키텍처 브레인스토밍  
> 상태: 확정

---

## 1. 시스템 철학

- **팩트 기반 전문 가이드** — 추측·해석 없이 MD-process·ra-project 내 팩트만 출처 명시하여 답변
- 답변 구조는 사용자 역할 무관하게 동일
- Agent는 탐색·라우팅 전담 (Hermes/Claw류 접목), Bot은 찾은 팩트만 답변 — hallucination 구조적 차단

---

## 2. 3-레포 구조 확정

| 레포 | 역할 |
|------|------|
| MD-process | 회사 정책·지침·SOP (지식 소스 #1) |
| ra-project | RA 전문가 지식베이스 (지식 소스 #2) |
| ra-med-bot (Regula) | 두 레포 기반 사내 사용자 소통 챗봇 |

---

## 3. 기술 아키텍처

- **Agent** — MD-process·ra-project 탐색·라우팅 전담
- **Bot** — 찾은 팩트 + 출처 명시 답변
- **운영 서버** — 중고 워크스테이션 + Linux
- **데이터 보관** — 민감 원본은 NAS DS224+ (내부망)
- **GitHub** — 구조화된 .md 파일 동기화 계속 유지
- **사용자 규모** — 사내 20명

---

## 4. 미답변 처리 파이프라인

```
사용자 질문
→ Agent 탐색 (MD-process + ra-project)
→ [내부에 있음] 팩트 + 출처 답변
→ [내부에 없음] 외부 공식 소스 리서치
   → RA 담당자·관리자 검증
   → 해당 레포 저장
   → 이후 답변 가능
```

**외부 리서치 소스:** MFDS 공식사이트, FDA.gov, EUR-Lex 등 공신력 있는 출처만

---

## 5. GitHub Issue 연계

- 미답변 발생 → ra-med-bot GitHub Issue 자동 등록
- RA 담당자·관리자가 분류 판단 (ra-project Issue or MD-process Issue)
- 해당 레포 GitHub Issue 연계 등록
- Cowork 스케줄링이 Issue 기반으로 처리
- 완료 후 bot 지식베이스 자동 업데이트

---

## 6. 대화 이력·감사 추적

- 목적: 내부 운영 기록
- 미답변 패턴 → ra-project BACKLOG 반영 → 지식베이스 우선순위 보완
- Bot 대화 이력이 지식베이스 자기 강화 사이클의 입력 소스
- ra-project 내부 스케줄(완성도 중심) + bot 미답변 BACKLOG(현장 긴급도 중심) 상호 보완

---

## 7. 알림 시스템

- 미답변 발생 → RA 담당자·관리자 이메일 알림
- 발송 방식: 일일 배치
- 발송 시점: 업무 시작 전 (08:00)
